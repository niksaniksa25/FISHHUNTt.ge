# Feedback and Analytics

- A floating “Feedback / შეცდომა” button is available on all root-level app pages, including the admin page.
- Feedback is saved on the Node server in `feedback.json` and appears in `admin.html` after administrator login. Admin can mark reports as read/resolved.
- On GitHub Pages without a configured API, the button prepares a report in this repository's [GitHub Issues](https://github.com/niksaniksa25/FISHHUNTt.ge/issues). The visitor needs a GitHub account and must press **Create issue** on GitHub to submit it. This is a public report, not a private admin-inbox submission. The optional email and the page's query string/fragment are omitted. For long messages, the link includes an excerpt and a copy button supplies the complete text.
- Reports are acknowledged as sent only after the API confirms durable storage. Validation and rate-limit errors remain visible with the draft intact; connection failures offer the GitHub alternative. Drafts stay in the current tab's session storage until confirmed submission or until the tab is closed. The dialog supports keyboard focus containment, Escape, and focus restoration.
- The backend tracks anonymous browser IDs and page views in `analytics.json`; it does not save IP addresses. Clear browser storage or use another browser/device and it is counted as another anonymous visitor.
- Successful registrations are reflected from `users.json`; successful sign-ins are counted in `analytics.json`.
- Orders are persisted in `orders.json`. Purchase reporting counts callback statuses received as successful from BOG and stores the summary in `analytics.json`. Ensure BOG merchant callbacks are correctly configured before relying on purchase totals for accounting.
- For the private feedback inbox, run `npm start` (or `START_GeoNature.bat` on Windows), then open the Node server's URL. VS Code Live Server and `file://` do not provide the Node API; their feedback option is the GitHub report flow.
- Set `GEONATURE_DATA_DIR` to a private writable directory outside the checkout; in production it must use persistent storage. Configure `GEONATURE_ADMIN_PANEL_PASSWORD` securely in the server environment for inbox access. Do not commit runtime JSON files or secrets. See [deployment instructions](DEPLOYMENT-FEEDBACK.md) to connect a separately hosted Node API to GitHub Pages.
